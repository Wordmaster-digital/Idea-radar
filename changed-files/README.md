# Idea-radar

예비창업자가 고객 문제·사업모델·시장 검증 방법을 찾도록 돕는 디스코드 창업정보 알리미.
인기 뉴스 순위 대신 **창업에 활용할 구체적인 단서가 있는 자료**를 선별한다.

## 자료출처

| 키 | 출처 | 탐색 범위 |
|---|---|---|
| `hn` | Show / Ask HN — Algolia API | 만든 서비스와 실제 고객 문제 질문. 일반 인기 뉴스는 수집하지 않음 |
| `ph` | [Product Hunt](https://www.producthunt.com/feed) | 대상 고객과 용도가 드러나는 제품 사례 |
| `fr` | [First Round Review](https://review.firstround.com/) 공식 RSS | 고객 인터뷰, 초기 고객 확보, PMF, 가격·수익화, 창업 실행 사례 |
| `yc` | [Y Combinator](https://www.ycombinator.com/blog) 공식 RSS | 창업자의 실행 자료·사례. 투자사 인사와 단순 발표는 제외 |
| `platum` | [플래텀](https://platum.kr/feed) | 국내 창업 실무·사업모델·검증 사례와 모집 정보 |
| `vsq` | [벤처스퀘어](https://www.venturesquare.net/feed) | 국내 창업 활용 정보. 투자유치·행사 성료 등 단순 보도는 제외 |

기본 키는 `hn,ph,fr,yc,platum,vsq`. 기존 GitHub·디자인·하드웨어·산업 피드는 `--sources`로 선택할 수 있지만 같은 창업정보 필터를 거친다. 기본 실행에서는 이들 범용 피드를 수집하지 않는다. 표의 탐색 범위는 선별 기준이며 모든 자료가 반드시 포함된다는 뜻은 아니다.

## 선별 기준과 게시 내용

`startup_focus.py`가 모든 출처에 공통으로 적용된다.

- **고객 문제·수요**: 반복되는 불편, 수작업, 고객 이탈과 기존 대안.
- **사업모델·수익화**: 지불 고객, 가격, 매출 구조, 수익화 사례.
- **고객 확보·검증**: 고객 인터뷰, 초기 고객 확보, PMF, 유료 전환.
- **창업 실행자료**: 창업자 사례, 실패 교훈, 실행 가이드.
- **서비스·제품 사례**: 구체적인 고객과 해결 방식이 함께 제시된 사례.
- **창업 프로그램**: 기본 피드에 포함된 관련 모집·교육·지원 정보. 공식 공고 전체를 수집하는 별도 봇은 아니다.

투자유치·인사·정치·실적·제품 발표만 있는 자료는 제외한다. 투자유치 전략이나 고객 확보 과정이 설명된 사례는 허용한다. Show HN 및 Product Hunt의 실제 제품 소개는 고객·용도가 확인될 때 허용한다. '스타트업'이라는 단어만 포함된 기사는 통과하지 않는다.

선별은 상위 개수 제한 **이전**에 수행한다. 창업 관련성을 먼저 정렬하고 인기도·최신성은 보조 기준으로 사용한다. 추적 URL 중복을 제거하며, 조건을 통과한 자료가 없으면 개수를 채우기 위해 뉴스를 넣지 않고 발송을 생략한다. 소스/분야별 비중은 먼저 다양하게 고르기 위한 목표이며, 남는 자리는 선별을 통과한 자료만 추가한다.

디스코드는 **출처·제목·분류·내용·창업 활용 관점·원문 링크**를 표시한다. 선택한 LLM이 원문에서 추출한 고객·문제·수익모델이 있으면 덧붙이고, 없는 내용은 만들지 않도록 요청한다. LLM이 없으면 규칙으로 분류·활용 관점을 표시하고 원문 설명을 제공한다. 긴 메시지는 1,900자 이하로 분할하며 원문에서 유입되는 전체 멘션은 비활성화한다.

## 실행

Python 3.11 이상, 표준 라이브러리만 사용한다.

```bash
python3 -m unittest discover -s tests -v
python3 daily_digest.py --dry-run
python3 daily_digest.py --top 20 --sources hn,ph,fr,yc,platum,vsq
```

`--dry-run`은 디스코드만 미발송하며 자료 조회와 선택적 LLM 호출은 수행한다. 외부 요청 없는 검증에는 테스트 명령을 사용한다.

기본으로 최근 72시간 자료를 대상으로 한다. `--max-age 168`로 일주일로 늘릴 수 있고, `--max-age 0`은 기간 제한을 해제한다. 날짜가 없거나 해석할 수 없는 원본은 기존 동작대로 24시간으로 취급하므로 최신 자료라고 확정하면 안 된다. 실행 간 발송 이력은 저장하지 않아 기간이 겹치면 같은 자료가 다시 발송될 수 있다.

## GitHub Actions 설정

기존 일정인 **매일 08:00 KST** (`0 23 * * *` UTC)를 유지한다. 수집·발송 전에 테스트를 실행한다.

| Actions Secret | 용도 | 미설정 시 |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | 대상 채널 발송 | 실제 발송 모드에서 오류 |
| `ANTHROPIC_API_KEY` | 선택적 한국어 요약·창업 관련성 검토·제품 사례 대조·아이디어 후보 | 규칙 기반 선별과 원문 설명 사용 |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | LLM이 만든 키워드로 국내 웹 근거 조회 | 네이버 검색 생략 |

LLM 키를 설정한 실행은 Anthropic API 이용료가 발생할 수 있다. 키를 추가하지 않으면 LLM은 호출하지 않는다. 기존 `idea_ladder_prompt.md`, `kr_check.py`는 별도 심층 검증 도구로 유지한다.

## 국내 유사 서비스 대조와 한계

제품 사례만 국내 서비스 대조 대상으로 삼는다. 일반 창업 가이드·모집 정보에 '한국 시장 공백' 판정을 붙이지 않는다. 단순 앱 검색 무응답이나 LLM 입력의 근거 부족은 **미확인/불명**으로 표시한다. '검색 범위 내 미발견'도 한국에 해당 사업이 없다는 확정 결론이 아니다. `--only-gaps`는 기존 옵션을 유지하되 LLM이 '없음'으로 분류한 제품 후보만 제한하며, 규칙 기반 실행에서는 확정 공백 후보를 만들지 않는다.

제목과 피드 설명에 의존하는 규칙이므로 모호한 제목·짧은 설명은 누락/오분류될 수 있다. LLM 필터는 보조 수단이며 실패하면 이미 규칙을 통과한 자료만 남긴다. RSS/API 접근 제한은 소스별 로그로 표시한다. 테스트는 네트워크 없이 정상/제외 사례·실제 창업 글 제목·Atom 링크와 날짜·게시 필터·LLM 실패·메시지 분할을 검증하며, 모든 외부 소스의 실시간 가용성을 보장하지 않는다.
